## 0. 全体構成（3画面 / ロール）

ロールは `UserRole`（[prisma/schema.prisma](../prisma/schema.prisma)）に定義済み。

| 画面 | ロール | 範囲 |
|---|---|---|
| **ユーザー画面**（研修参加者） | `participant` | 自分の研修（事前→Day1→宿題→Day2→事後）を進める |
| **講師画面**（進行役） | `admin` | 研修の参加者を見る・当日進行を支援。権限は事務局と同じ（2層） |
| **事務局画面**（全体管理） | `admin` | 全研修・全参加者・会社・日程・メール等を統括 |

データの紐付け: `WorkshopSession`（研修コード）⇄ `User`（参加者・会社・部署）⇄ `WorkshopData`（成果物）。
講師は「担当する WorkshopSession」単位、事務局は全体。

## 1.5 運用モード（同期/非同期 × フォーマット）※2026-06 確定

2軸で全フェーズを分類する。

**軸A：運用**
- **同期・集合（研修時のみ）**: Day1 / Day2 … 複数参加者＋講師が同時刻。期間限定で開放。
- **個別・非同期（各自の都合で）**: 事前課題 / 宿題 / 事後アンケート … 各自のペース。前後の窓で開放。

**軸B：フォーマット／対応デバイス**
- **アンケート（レスポンシブ・スマホOK）**: 事前アンケート / 事後アンケート
- **ワークシート（PC前提・1123px=A4横・PDF出力可）**: じぶん紹介(事前) / Day1 / 宿題 / Day2

| フェーズ | 運用 | フォーマット |
|---|---|---|
| 事前アンケート | 個別・非同期 | アンケート(レスポンシブ) |
| じぶん紹介 | 個別・非同期 | ワークシート(PC/A4) |
| Day1 | 同期・集合 | ワークシート(PC/A4) |
| 宿題 | 個別・非同期 | ワークシート(PC/A4) |
| Day2 | 同期・集合 | ワークシート(PC/A4) |
| 事後アンケート(直後/3ヶ月) | 個別・非同期 | アンケート(レスポンシブ) |

**「同期」の実装方針（重要）**
- 「同期」＝**緩い同期**。講師が**セクションを順に開放** → 参加者は各自のデバイスで各自のペースに記入。
- → **リアルタイム追従（websocket/Realtime）は不要。** 既存のフェーズ開放(ゲーティング)を**セクション粒度に拡張**し、**進行役（admin）が操作**する形にする。
- 当日の参加者入力は**各自のデバイス**（ノートPC想定）。ワークシートは1123px(A4横)固定なので**ノートPC〜PCで成立**（スマホ最適化はしない）。講師は自分のPCから1920で投影。
- → Day1/Day2の各ワークは「**セクション**」として開放制御できる構造にしておく（§2 F-4）。

**出力・閲覧（全ゾーン共通）**
- 「出力なし」のフェーズは無い。**どのフェーズも参加者は自分の記入を閲覧・PDF出力できる**。
  - ワークシート（じぶん紹介/Day1/宿題/Day2）= **A4横PDF**（window.print）＋画面閲覧
  - アンケート（事前/事後）= 該当HTMLページで自分の回答を閲覧
- まとめ閲覧は終了後の「受講生ダッシュボード（read-only＋PDF）」で集約（§3.1 A-6 / Step7）。

**参加者への入力推奨（事務局案内・要記録）**
- 事前課題（特にじぶん紹介＝PCワークシート）は **PCでの入力を推奨**。事務局が招待メール／扉ページで案内する。
- じぶん紹介の**スマホ最適化はしない**（PC前提のまま）。

## 1.6 2プログラム構成（ルート・テーマを分離）※2026-06 確定

同一ログインだが、**運営・デザインを2つのプログラムに分ける**。データは WorkshopData
（pre/day1/homework/day2/post）で一元のまま、**IA（ルート）とテーマだけ分離**する。

**Program A — 調査＋じぶん紹介（ダーク／未来感）**
- 事前アンケート（レスポンシブ）／ **じぶん紹介**（白A4シート・PC）／ 事後アンケート 直後・3ヶ月（レスポンシブ）
- ルート：既存 `/workshop`（ダークテーマ）
- ※「じぶん紹介」は本プログラム(ダーク)で**入力**（白シートがダークステージに載る現状のまま・ユーザー確定）

**じぶん紹介のデータフロー（確定）**
- 入力＝Program A（ダーク）`/workshop/pre/profile-slide`。データは `WorkshopData.pre.profileSlide` に1か所保持。
- 表示＝Program B（ライト・Day1）で**同じデータを Supabase から読み込み、発表用に読み取り専用で表示**。
- → Day1（ライト）に「じぶん紹介（read-only）」ビューを置く。シート描画は共有コンポーネント化して再利用する。

**Program B — 研修本番（全面ライトテーマ）**
- Day1（講義・じぶん分解・じぶん分析）／ 宿題（みらいシナリオ）／ Day2（ビジョン・資本・シフト）
- ルート：**新設・専用レイアウト**で全面ライト（背景・ヘッダー・ボタンも白基調）
- 緩い同期（講師がセクション開放）。宿題のみ非同期。

→ ログイン後は両プログラムへ行ける入口を用意（同一アカウント）。
→ 既存の `WorksheetStage`（ダーク）は Program A の じぶん紹介用。Program B には**ライト版の枠**を用意する。

**実装状況（2026-06）**: Program B の枠は構築済み。
- ルート `/training`（+ `/training/day1|homework|day2` プレースホルダ）／ ライトレイアウト `app/training/layout.tsx`＋`TrainingHeader`
- ダッシュボード `app/training/page.tsx`（白基調・講師開放に応じて表示）。`.worksheet-stage` は背景無しなのでライトレイアウト配下でそのまま白くなり再利用可
- `/workshop`（Program A）から「研修本番へ」カードで誘導。`lib/phases.ts` に `program: A|B` を追加し Day1〜のルートを `/training/*` に変更
- 次: Day1 の中身（講義／じぶん分解／じぶん分析）＋ じぶん紹介 read-only ビュー

### 設計メモ：好き・得意分析の心理（AI対話用）
じぶん分析の「好き・得意マトリクス」は、受講生の**動機の質**を読み解くためのもの。AI対話はこの軸で解釈する。
- **好き** ＝ それをやること自体が好き／自分のため／力が湧いてくる ＝ **内発的動機（intrinsic）**
- **得意** ＝ 能力を褒められると嬉しい／誰かのため／役に立つ実感 ＝ **他者貢献・承認（contribution）**
- 「個人／会社」軸と掛け合わせ、内発と貢献のバランス・伸ばしどころをAIが対話で引き出す。

## 6. リハーサル運用（役割別ライブ点検）

**目的**: プレビューが単一セッションな制約を「役者を分ける」ことで回避し、参加者／講師／事務局の3視点で
画面内容・遷移・連動（通知/開放）の不具合を洗い出す。＝ 自動テストではなく**ライブの通し点検**。

**成立の鍵**: ローカルプレビューも Vercel本番も**同じ Supabase** を見ている（DATABASE_URL 同一）。
よって別ブラウザ・別PC・エージェントがどこから入っても同じ状態を共有でき、ハンドオフ（招待→提出→閲覧→開放）が一周する。

**役者の割り当て**
| 役 | 誰が | 手段 |
|---|---|---|
