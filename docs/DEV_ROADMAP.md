## 0. 全体構成（3画面 / ロール）

ロールは `UserRole`（[prisma/schema.prisma](../prisma/schema.prisma)）に定義済み。

| 画面 | ロール | 範囲 |
|---|---|---|
| **ユーザー画面**（研修参加者） | `participant` | 自分の研修（事前→Day1→宿題→Day2→事後）を進める |
| **講師画面**（担当講師） | `facilitator` | 担当する研修コードの参加者を見る・当日進行を支援 |
| **事務局画面**（全体管理） | `admin` | 全研修・全参加者・会社・日程・メール等を統括 |

データの紐付け: `WorkshopSession`（研修コード）⇄ `User`（参加者・会社・部署）⇄ `WorkshopData`（成果物）。
講師は「担当する WorkshopSession」単位、事務局は全体。

## 1.5 運用モード（同期/非同期 × フォーマット）※2026-06 確定

2軸で全フェーズを分類する。

**軸A：運用**
- **同期・集合（研修時のみ）**: Day1 / Day2 … 複数参加者＋講師が同時刻。期間限定で開放。
- **個別・非同期（各自の都合で）**: 事前課題 / 宿題 / 事後アンケート … 各自のペース。前後の窓で開放。

**軸B：フォーマット／対応デバイス**
- **アンケート（レスポンシブ・スマホOK）**: 事前アンケート / 事後アンケート
- **ワークシート（PC前提・1123px=A4横・PDF出力可）**: じぶん紹介(事前) / Day1 / 宿題 / Day2

| フェーズ | 運用 | フォーマット |
|---|---|---|
| 事前アンケート | 個別・非同期 | アンケート(レスポンシブ) |
| じぶん紹介 | 個別・非同期 | ワークシート(PC/A4) |
| Day1 | 同期・集合 | ワークシート(PC/A4) |
| 宿題 | 個別・非同期 | ワークシート(PC/A4) |
| Day2 | 同期・集合 | ワークシート(PC/A4) |
| 事後アンケート(直後/3ヶ月) | 個別・非同期 | アンケート(レスポンシブ) |

**「同期」の実装方針（重要）**
- 「同期」＝**緩い同期**。講師が**セクションを順に開放** → 参加者は各自のデバイスで各自のペースに記入。
- → **リアルタイム追従（websocket/Realtime）は不要。** 既存のフェーズ開放(ゲーティング)を**セクション粒度に拡張**し、**講師(facilitator)が操作**する形にする。
- 当日の参加者入力は**各自のデバイス**（ノートPC想定）。ワークシートは1123px(A4横)固定なので**ノートPC〜PCで成立**（スマホ最適化はしない）。講師は自分のPCから1920で投影。
- → Day1/Day2の各ワークは「**セクション**」として開放制御できる構造にしておく（§2 F-4）。

**出力・閲覧（全ゾーン共通）**
- 「出力なし」のフェーズは無い。**どのフェーズも参加者は自分の記入を閲覧・PDF出力できる**。
  - ワークシート（じぶん紹介/Day1/宿題/Day2）= **A4横PDF**（window.print）＋画面閲覧
  - アンケート（事前/事後）= 該当HTMLページで自分の回答を閲覧
- まとめ閲覧は終了後の「受講生ダッシュボード（read-only＋PDF）」で集約（§3.1 A-6 / Step7）。

**参加者への入力推奨（事務局案内・要記録）**
- 事前課題（特にじぶん紹介＝PCワークシート）は **PCでの入力を推奨**。事務局が招待メール／扉ページで案内する。
- じぶん紹介の**スマホ最適化はしない**（PC前提のまま）。

## 6. リハーサル運用（役割別ライブ点検）

**目的**: プレビューが単一セッションな制約を「役者を分ける」ことで回避し、参加者／講師／事務局の3視点で
画面内容・遷移・連動（通知/開放）の不具合を洗い出す。＝ 自動テストではなく**ライブの通し点検**。

**成立の鍵**: ローカルプレビューも Vercel本番も**同じ Supabase** を見ている（DATABASE_URL 同一）。
よって別ブラウザ・別PC・エージェントがどこから入っても同じ状態を共有でき、ハンドオフ（招待→提出→閲覧→開放）が一周する。

**役者の割り当て**
| 役 | 誰が | 手段 |
|---|---|---|
| 参加者（5名想定） | エージェント | アプリのAPIを直接叩いて入力（堅牢）。UIクリックが要れば2つ目のプレビュー(別ポート)も可 |
| 講師 | 太田さん | Vercel本番URLを別ブラウザ/別PCで（※講師画面が出来てから） |
| 事務局 | Claude | プレビューで進行確認・ナレーション（スクショはチャットに出るので太田も同時に見られる） |

**ダミーデータ運用（重要・実データは絶対に触らない）**
- namespace で識別: メール `@rehearsal.thirdage.test` / 研修コード `REHEARSAL` / 会社名プレフィックス `[リハ] ` / 共通PW `rehearsal`
- 開始時: **`npm run rehearsal:setup`** … 参加者5・講師1・会社2・研修セッション1（Day1=2週後/Day2=3週後）を投入。全員**即ログイン可**
- 終了後: **`npm run rehearsal:teardown`** … namespace一致分を**完全削除**（User削除でWorkshopDataはCascade、Session削除でBlockStatusはCascade）
- **常駐させない。** 次回リハはまた setup から立ち上げる
- 実装: [scripts/rehearsal-setup.ts](../scripts/rehearsal-setup.ts) / [scripts/rehearsal-teardown.ts](../scripts/rehearsal-teardown.ts) / [scripts/rehearsalData.ts](../scripts/rehearsalData.ts)

**実施タイミング**: 3〜4回の節目（① ユーザー画面 一通り完成 ② 講師画面 完成 ③ 事務局＋連動 実装後 ④ リリース前）。
現状は講師画面が無いので、フル3者は講師画面完成後。それまでは「参加者エージェント＋Claude事務局」の2者ミニ・ドライランで形式確認は可能。
