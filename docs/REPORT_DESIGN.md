# 受講者レポート 設計ノート

事後アンケート提出後に本人が受け取る **「じぶん経営 戦略講座 ○○さんレポート」** の設計。
ワークシートに書かれた記述をAIで読み解き、A4横1枚にまとめて返す。

このドキュメントは **プロンプトをチューニングしていくための土台** として書いている。
「なぜこの材料を選んだか」「なぜこの制約を置いたか」を残すことが目的で、
文言の微調整はコード側（`lib/report/prompt.ts`）で行い、方針が変わったときにここへ戻す。

- 実装: `lib/report/source.ts`（材料の抽出）／ `lib/report/prompt.ts`（システムプロンプト）
- 画面: `/workshop/check`（入口は `/workshop/records` の「レポートをみる」）
- 関連: [WORKSHEET_DESIGN.md](WORKSHEET_DESIGN.md)（A4横スライドの寸法規定）

---

## 1. 目指すアウトプット

### 1.1 なぜ作るのか

研修で書いたワークは20種類ある。一つひとつは本人の言葉だが、**バラバラのままでは
「自分がどう変わったか」が見えない**。レポートの役割は、散らばった記述を
「働くことへの意識」「会社での経営」「社会での経営」の3つに束ね直し、
研修が終わったあとも手元に残る一枚にすることにある。

リード文はこの意図をそのまま伝える：

> 講座の内容をもとにレポートを作成しました。今後の「じぶん経営」にご活用ください。

### 1.2 レイアウト

A4横スライド（1100×710px）の規定に従い、**PDFで持ち帰れること**を前提とする。

左右2列 × 各2カード、計4カード。

```
┌──────────────────────────────────────────────────────┐
│ じぶん経営 戦略講座　○○さんレポート      株式会社COMMUNITY │
│ 講座の内容をもとにレポートを作成しました。…                │
├───────────────────────┬──────────────────────────────┤
│ ○○さんの「じぶん経営」方針│ 会社における「じぶん経営」      │
│ ミッション／ビジョン／    │ （AI分析・200字／5行）          │
│ バリュー（AI・MVV）      ├──────────────────────────────┤
├───────────────────────┤ 社会に対する「じぶん経営」      │
│ 働くことへの意識の変化    │ （AI分析・200字／5行）          │
│ 棒＋折れ線の複合グラフ    │                              │
└───────────────────────┴──────────────────────────────┘
```

**高さは固定（`h-[521px]`）。** シート710px から余白80・見出し52・リード25・
各マージンを引いた残り。内容量にかかわらずシートが710pxに収まるようにするため
（超えると印刷が2ページに割れる）。グラフはこの中で残った高さを埋めるよう伸縮する。

### 1.3 左側：働くことへの意識の変化

- **縦棒**: §A / §B / §C の3区分ごとに「事前」「事後」を並べる（各区分内の設問平均）
- **折れ線**: 調査母体の平均値を重ねる

当初レーダーチャート（13軸）で試作したが、軸が多すぎて差が読み取れなかったため
**3区分に集約した棒＋折れ線**に変更した。

> #### ⚠️ §A〜§C に重ねられる母体平均は存在しない（2026-08-27 調査済み）
>
> 出典の調査を全ページ確認した結果、**5段階評価の平均値はどこにも載っていない。**
> 図1〜図9はすべて選択肢の構成比（%）で、リッカート尺度の設問自体が無い。
>
> - 出典: 公益財団法人 産業雇用安定センター「ミドルシニア世代のセカンドキャリアに関する意識調査」
>   （2025年7月・Web調査・n=900／対象: 45〜59歳、従業員300人以上かつ60歳定年—65歳までの
>   継続雇用制度を有する企業に15年以上勤務する社員）
> - PDF: https://www.sangyokoyo.or.jp/topics/2025/s0r8v000000026mw-att/mid-senior-secondcareer-jobsanko.pdf
>
> したがって `BENCHMARK` は null のままで、**折れ線は描かれない**。
> 数値を作って埋めてはいけない。再調査の前にこの節を読むこと。

比較が成立するのは **§D だけ**。§D は同調査の図1と設問文・選択肢6つが完全に一致する
（もともとそのために設計された）。実データは §1.4 に控えてある。

| 区分 | 内容 | 設問 |
|---|---|---|
| §A | キャリア自律意識 | a1〜a6（6問） |
| §B | 自己理解 — Will / Can / Must | b1〜b3（3問） |
| §C | 行動意図・つながり | c1〜c4（4問） |

### 1.4 §D と母体の比較データ（検証済み・そのまま使える）

出典調査の**図1「今後の働き方に対するイメージ」全体（n=900）**。
`lib/surveyContent.ts` の `SECTION_D.options` と value が1対1で対応する。

| value | 選択肢 | 母体 |
|---|---|---|
| `1` | 定年前に、転職または独立したい | 5.3% |
| `2` | 定年を契機に、転職または独立したい | 9.9% |
| `3` | 定年後は同じ会社（グループ）で雇用延長し、そこから転職または独立したい | 7.3% |
| `4` | 定年後は同じ会社（グループ）で雇用延長し、そこで働くのをやめたい | 23.7% |
| `5` | 定年をもって働くのをやめたい | 22.4% |
| `6` | まだ決めていない | 31.3% |

参考: 「まだ決めていない」を除くと（n=618）転職希望 32.9% ／ 雇用延長して辞めたい 34.5% ／
定年で辞めたい 32.7% と三分される。55〜59歳では転職希望が 39.3% に上がる（図1②）。

同様に、§Dの分岐設問も図2〜図5に対応する（`lib/surveyContent.ts` のコメント参照）。

### 1.5 左上：じぶん経営方針（MVV）

会社が MISSION / VISION / VALUE を掲げるのと同じ形で、その人個人の経営方針を言葉にする。
研修の図版にある **MVV ↔ WCM の対応** をそのまま使う。

| 方針 | 元になるWCM | 研修での言い方 |
|---|---|---|
| ミッション（存在意義） | **Must** | 本分・使命 |
| ビジョン（ありたい姿） | **Will** | ありたい姿 |
| バリュー（行動指針） | **Can** | 役割と責任 |

字数はカードに収める都合で厳格に決めている。**ミッション・ビジョンは各30字以内で1行、
バリューは3つ以内・各20字以内。** 3項目に分かれるため、この枠だけAIに**JSONで返させる**
（`{"mission": "...", "vision": "...", "values": [...]}`）。前置きやコードブロックが
付いてきても拾えるよう、最初の `{...}` を取り出してパースする。

材料は会社軸・社会軸の両方から引く（方針は両方を束ねたものなので）。
主な出所は Day2 の **WCM 3.0** と **#19 課題・目標・行動**、および両シナリオ。

### 1.6 右側：AI分析文（2枠）

会社軸・社会軸それぞれ **約200字・5行**。両方とも同じ3点構成にする。

1. 研修前、その領域で **何を重視していたか**（出発点）
2. 研修を通じて **これからどうしたいと考えるようになったか**（到達点）
3. その考えへの **ポジティブメッセージ ＋ 要注意事項**

①→②で変化の物語を描き、③でそれを後押しする。**評価や格付けではない**。

## 3. 抽出方針

### 3.1 考え方：「前後のペア」を軸に選ぶ

AIに全部渡せば良いレポートが出るわけではない。分量が増えるほど的が絞れず、
一般論に流れる。そこで **出力させたい3点構成に、材料の側をあらかじめ対応させる**。

決め手にしたのは「**同じ問いに、研修の前と後で2回答えているワークがあるか**」。
このペアがあれば変化を語れる。特に次の2つが軸になる：

- **会社軸 = WCM 2.0 → 3.0**（#18）— 同一フォーマットで前後を書いている
- **社会軸 = ポートフォリオ（#5）→ ポートフォリオ3.0（#15）** — 同上

### 3.2 材料の振り分け

| 分析の観点 | 会社軸 | 社会軸 |
|---|---|---|
| ① 何を重視していたか（出発点） | ⑧じぶん∩会社、⑥好き得意(会社行)、⑱WCM **2.0**、②今の仕事q1-q3 | ⑨社会との接点、⑤ポートフォリオ**現在**、④分人シェア表 |
| ② どうしたいと考えるようになったか（到達点） | ⑪会社編シナリオ、⑱WCM **3.0**、⑲課題・目標・行動 | ⑫社会編シナリオ、⑰バックキャスト、⑮ポートフォリオ**3.0**＋シフトポイント、⑯アクションプラン |
| ③ 励まし＋要注意（裏づけ） | ⑦働く動機の源泉、⑬資産表、⑳a1/a4/b3/c1の変化 | ⑩プチ越境体験（実体験）、⑳c2/c3/c4/a5の変化 |

両軸に共通で、**②じぶん紹介**と**⑬資産表**を「この方について」として前置きする。
どんな立場の人が書いているかが分かると、同じ記述でも読み解きが変わるため。

### 3.3 意図的に渡していないもの

| ワーク | 渡さない理由 |
|---|---|
| ③ライフラインチャート | 数値の起伏であり、言語化された意図がない。文章の材料になりにくい |
| ⑭コミュニティ活動力診断 | スコアのみ。AIに渡すと「点数が低い」という**格付け的な言及**を誘発する。数値はグラフで見せる領域と割り切る |
| ⑩越境体験の対話ログ全文 | 長大。決めた企画（decision.summary）とレポートだけで十分足りる |

いずれも「渡せない」のではなく「**渡すと出力が悪くなる**」という判断。
チューニングで足す余地はあるが、足すときはこの理由を覆せるか確認する。

### 3.4 実装上の約束（`lib/report/source.ts`）

- **形式は「【見出し】ラベル: 本文」のプレーンテキスト。** JSONで渡すより、
  空欄の多い実データで安定する。
- **空欄の行は落とす。** 空のキーを見せるとAIが推測で埋めようとする。
- **事前→事後の5段階回答は `3 → 5` の形に整形して渡す。** 数値の生ペアより変化が読める。
- **材料が40字未満なら `null` を返す。** ほとんど記入がない人にAIを叩かず、
  画面側で「記入が少ない」旨を出すため。

### 3.5 字数の最終ガード

カードは高さ固定のため、あふれると下が切れて読めなくなる。プロンプトで字数を
指定しても**モデルは超過する**（実測: 200字指定に対して228〜291字）ので、
保存前にコード側でも落とす（`generate.server.ts`）。

- 会社軸・社会軸の本文: **260字**。ただし途中で切ると文章が壊れるので、
  **句点（。）単位で落とす**（`clampSentences`）
- MVV: mission / vision 30字、values 各20字・3つまで

このガードは保険であり、常用する前提ではない。頻繁に発動するようなら
プロンプト側（§4.1「分量」）を締め直す。

## 4. プロンプト設計

`lib/report/prompt.ts`。軸ごとに `AXIS_META`（対象範囲・注目点）を差し替え、
本体の指示は共通にしている。

### 4.1 置いた制約と、その理由

| 制約 | なぜ |
|---|---|
| **本人の言葉をそのまま活かす** | 言い換えて一般論にならすと「自分のレポート」に見えなくなる。ここが読み手の納得を左右する最重要点 |
| **200字前後・見出しなしの地の文** | A4横1枚に2枠入る物理的な上限。箇条書きにすると行数が読めずレイアウトが崩れる |
| **診断・格付けをしない** | 「優れています」「不足しています」は研修の趣旨に反する。役割は変化を見つけて言葉にすること |
| **要注意事項は否定でなく助言の形** | 最後に否定で終わると持ち帰る気が失せる。「ここに気を配ると進みやすい」に変換させる |
| **空欄への言及を禁止** | 「〇〇が未記入です」は本人を責める文章になる。書かれていることだけで組み立てさせる |
| **推測・創作の禁止** | 勤務先の事情・家族構成など、材料にない事実を書かれると信頼を一発で失う |
| **「あなた」と呼びかけない** | 読み手は本人だが、二人称は説教くさくなる。「〜と書かれています」と記述をなぞる距離感にする |
| **カタカナ用語を避ける** | ミドルシニアの可読性最優先（[DESIGN_GUIDELINES.md](DESIGN_GUIDELINES.md)）。ただし Will/Can/Must は研修中の用語なので許可 |

### 4.2 チューニングするときの勘所

出力に不満が出たとき、どこを触るかの目安：

| 症状 | 疑う場所 |
|---|---|
| 一般論っぽい・誰にでも当てはまる | 材料不足。`source.ts` の振り分け（3.2）を見直す |
| 長すぎる／短すぎる | `prompt.ts` の「## 分量」 |
| 変化が描けていない | 前後ペア（3.1）が材料に入っているか。空欄で落ちていないか |
| 要注意事項がきつい | 「否定ではなく助言の形」の例示を増やす |
| 事実でないことを書く | 「書いてはいけないこと」に具体例を追加する |

**変更したら、記入の薄い人・厚い人の両方で必ず出力を確認する。**
材料が少ないときに破綻しやすい。

## 5. 生成タイミングと保持

**初回に一度だけ生成し、以後は保存済みを表示する。** 毎回生成しない理由は3つ：

1. **同じ人に毎回違う文章が出るのは困る。** レポートは持ち帰って読み返すもの。
   開くたびに表現が変わると「さっき読んだ文はどこへ行った」となる。
2. **PDFで保存した紙と、画面の内容が食い違わない。**
3. コストと待ち時間（生成中の空白）を、初回だけに閉じ込められる。

| 項目 | 決めたこと |
|---|---|
| 保存先 | `post.report`（`{ company, society, generatedAt }` を想定） |
| 生成の起点 | レポート画面を最初に開いたとき。保存済みがあればAIを叩かない |
| 再生成 | ワークを書き直した人のために、**明示操作での再生成**を用意する（自動再生成はしない） |

> 材料が薄く `buildReportSource()` が `null` を返した場合は保存しない。
> あとからワークを書き足したときに、初回の空レポートが固定されてしまうため。

### 5.1 使用モデル

**`claude-opus-5`**（`lib/report/generate.server.ts`）。対話系の Haiku 4.5 とは分けている。

当初 Haiku 4.5 で組んだところ、**200字指定に対して320〜390字を出力し、
制約を守れなかった**。プロンプト側で「240字を絶対に超えない」「6文以内」まで
強めても超過が続いたため、モデルを上げて解決した（248字まで収束）。

字数だけでなく内容も変わった。Haiku は材料が薄いと**アンケートの点数の話に逃げる**
（「4段階で評価するようになりました」等）が、Opus 5 はワークに書かれた固有名詞
（「子ども食堂」「地域とのつながり」）を拾って具体的に書く。
本設計が最重要に置く「本人の言葉をそのまま活かす」（§4.1）に直結する差なので、
ここはモデルを下げない。

- 生成は受講者ひとりにつき1回だけ。呼び出し回数が少なくコスト影響は小さい
- 思考トークンも `max_tokens` に含まれるため、出力200字でも `max_tokens: 8000` を確保する
